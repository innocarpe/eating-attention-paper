# ADR-005: 모듈 시도 기록의 로컬 영속성 계약

- 상태: 승인됨
- 결정일: 2026-07-30

## 맥락 (Context)

학습자는 모듈을 여러 번 시도할 수 있으며, 완료된 결과와 중단된 시도를 구분해 보아야 한다. 진행 상태 갱신 중 브라우저가 종료되거나 저장이 실패해도 완료 포인터가 불완전한 기록을 가리키면 안 된다. 동시에 학습자 데이터는 로컬에 남아야 하고, 민감하거나 과도한 원문을 저장해서는 안 된다.

## 결정 (Decision)

모듈별 시도는 attempt-scoped 레코드로 저장한다. 종료 상태는 `complete` 또는 `abandoned`이며, 두 상태의 이력 레코드는 생성 후 불변(immutable)이다. 각 모듈에는 가장 최근의 **complete** 시도만 가리키는 `latestCompleteAttemptId` 포인터를 둔다. 시도를 complete로 기록하고 이 포인터를 갱신하는 작업은 하나의 원자적(atomic) 저장 트랜잭션으로 수행한다. `abandoned` 시도는 포인터를 변경하지 않는다. 저장소에는 원시 답안, 설명, 사용자 코드, 실행 출력 전문을 저장하지 않는다.

## 대안 (Alternatives)

- 모듈당 하나의 덮어쓰기 진행 레코드: 이력과 중단/완료 구분을 잃으므로 채택하지 않는다.
- 가장 최근 시도 포인터: abandoned 시도가 완료 결과를 가릴 수 있으므로 채택하지 않는다.
- complete 레코드와 포인터를 별도 비원자 작업으로 기록: 장애 시 깨진 참조나 불일치가 남으므로 채택하지 않는다.
- 답안·설명·코드 전문 저장: 최소 수집 및 로컬 학습 데이터 경계에 맞지 않아 채택하지 않는다.
- 원격 계정 동기화: 현재 로컬 우선 계약과 추가 데이터 처리 위험 때문에 채택하지 않는다.

## 결과 (Consequences)

각 시도는 고유 ID, 모듈 식별자, 종료 상태, 필요한 최소 메타데이터만 가진다. complete/abandoned 이력은 수정하거나 재사용하지 않고, 정정이 필요하면 새 시도를 추가한다. 읽기 로직은 `latestCompleteAttemptId`가 없으면 완료 없음으로 처리하고, 존재하면 같은 모듈의 immutable complete 레코드만 허용한다. 원자 트랜잭션을 지원하지 않는 저장소로 바꾸려면 동일한 all-or-nothing 보장을 설계·검증한 뒤 이 ADR을 갱신한다.

## 검증 (Verification)

**현재 확인된 사실**: complete/abandoned attempt-scoped immutable history, atomic latest complete pointer, 그리고 원시 답안·설명·코드 미저장이 승인된 계약이다. 학습자 데이터는 로컬에 둔다.

**릴리스 시 필요한 증거**:

1. complete 기록과 `latestCompleteAttemptId` 갱신이 단일 원자 트랜잭션임을 보여 주는 저장 구현 및 장애 주입 검사.
2. complete 저장 중단 시 새 포인터나 부분 complete 레코드가 관측되지 않음을 보여 주는 검사 기록.
3. abandoned 시도가 이력에는 남고 latest complete 포인터를 바꾸지 않음을 보여 주는 시나리오 기록.
4. 동일 모듈의 여러 complete 시도 후 포인터가 마지막 성공한 complete 레코드만 가리키며, 이전 레코드가 변하지 않음을 보여 주는 검사 기록.
5. 브라우저 저장소와 네트워크 요청 검토에서 원시 답안·설명·코드·실행 출력 전문이 없고 데이터가 로컬에만 있음을 보여 주는 기록.

## 실패 및 출시 금지 (Failure / No-go)

complete 포인터와 레코드 생성이 원자적이지 않거나 포인터가 abandoned/누락/다른 모듈의 레코드를 가리킬 수 있으면 출시하지 않는다. 완료 이력이 변경 가능하거나 원시 답안·설명·코드가 저장 또는 전송되면 출시 금지다. 저장 장애에서 일관성을 보장할 수 없으면 해당 영속성 기능을 활성화하지 말고 저장 경계와 트랜잭션을 수정한 뒤 모든 릴리스 증거를 다시 수집한다.
