# ADR-004: 분석 비활성 기본값과 증거 기반 활성화

- 상태: 승인됨
- 결정일: 2026-07-30

## 맥락 (Context)

학습 서비스의 분석은 개인정보, 학습 행태, 제3자 처리 위험을 늘린다. 분석 수집의 편의만으로는 이러한 위험을 정당화할 수 없으며, 학습자 데이터는 기본적으로 로컬에 남아야 한다.

## 결정 (Decision)

분석은 기본적으로 꺼 둔다. 다음 두 종류의 증거가 모두 존재할 때만 분석 기능을 활성화할 수 있다.

1. 처리자(processor), 로그(log), DPA(Data Processing Agreement), 보존 기간(retention)을 식별하고 검토 가능한 문서 증거.
2. 수집·전송·저장·삭제 범위가 위 증거와 일치함을 확인하는 구현 및 운영 증거.

분석이 꺼진 상태에서는 추적 스크립트, 추적 픽셀, 분석 SDK, 분석용 네트워크 전송을 로드하지 않는다. 원시 답안, 설명, 코드 및 학습 시도 내용은 분석에 전송하지 않는다.

## 대안 (Alternatives)

- 분석을 기본 활성화하고 나중에 동의 수집: 사전 증거 없이 데이터 처리를 시작하므로 채택하지 않는다.
- 익명화 주장만으로 활성화: 처리자·로그·DPA·보존 기간의 책임을 대체하지 못하므로 채택하지 않는다.
- 자체 수집 endpoint: 처리·로그·보존 책임이 사라지지 않으므로 증거 요건 없이 채택하지 않는다.
- 브라우저 로컬 통계: 전송하지 않는 한 분석 활성화로 취급하지 않지만, 원시 학습 내용을 장기 보관하는 용도로 사용하지 않는다.

## 결과 (Consequences)

코드와 배포 기본값은 분석 비활성이다. 활성화 설정은 명시적이고 검토 가능해야 하며, 부분 증거 또는 구두 확인으로는 켤 수 없다. 공급자나 수집 필드를 바꾸면 새 처리/로그/DPA/보존 증거와 구현 검증을 다시 받아야 한다. 분석이 필요 없는 제품 판단은 로컬·비전송 집계보다 우선한다.

## 검증 (Verification)

**현재 확인된 사실**: 분석은 off-by-default이며, 활성화에는 processor/log/DPA/retention을 다루는 두 필수 증거 범주가 필요하다. 학습자 데이터의 기본 위치는 로컬이다.

**릴리스 시 필요한 증거**:

1. 기본 배포에서 분석 도메인, SDK, pixel 요청이 없음을 보여 주는 네트워크 기록.
2. 활성화를 제안하는 경우, 처리자·로그·DPA·보존 기간 각각의 문서와 책임자를 담은 검토 기록.
3. 활성화 제안 시 실제 전송 필드, 목적, 수신처, 보존/삭제 동작이 문서와 일치함을 보여 주는 검사 기록.
4. 원시 답안·설명·코드가 분석 요청, 로그, 저장소에 포함되지 않음을 보여 주는 요청/로그 표본 검토.

## 실패 및 출시 금지 (Failure / No-go)

두 증거 범주 중 하나라도 없으면 분석은 계속 비활성으로 유지한다. 기본 배포에서 분석 요청이 발생하거나 원시 학습 내용이 분석으로 전송되면 분석 기능을 즉시 제거 또는 차단하고 출시하지 않는다. 문서와 실제 수집이 불일치하거나 보존 기간을 확인할 수 없는 경우에도 분석 활성화와 그 활성화가 포함된 릴리스는 금지다.
